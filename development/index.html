Development

How to build, test, and release Library, and how strings are localized.

Build

  • ./build.sh builds the app.

Every pull request and every push to main builds the app and runs the checks on GitHub Actions.

Test

./test.sh runs the checks in Tests/. They use private pasteboards and temporary files, so they never touch your clipboard or your library.

Releasing

Push a tag to publish a release:

git tag v1.2.0
git push origin v1.2.0

Or run the Release workflow by hand with a version. Either way, GitHub Actions builds and checks the app, then publishes Library-1.2.0.zip. The zip is the source, with only what's needed to build. The tests, workflows, docs, and icon script are left out.

If publishing fails with a server error, the workflow retries up to four times. Re-running it is safe, because it skips creating a release that already exists.

Languages

Library is in English. Strings live in Sources/Library/Resources/en.lproj/Localizable.strings. Write each user-facing string as Text("…", bundle: L10n.bundle), or String(localized: "…", bundle: L10n.bundle) where a String is needed. To add a string, add a "key" = "value"; line with a /* comment */ above it.

Dynamic text, such as file names, counts, and clipboard contents, isn't localized.
