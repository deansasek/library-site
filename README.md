This is the website for Library, a menu bar app for macOS. The app, its source code, and its releases live in the [library repository](https://github.com/deansasek/library).

## What the site contains

- A landing page that introduces Library and links to the install steps.
- A guide to every feature, setting, and permission.
- Pages on privacy, installing and updating, smart features, accessibility, and development.
- Release notes for each major and minor version, with a page for each one.

The site is static: plain HTML and CSS, with one small script for copy buttons and docs search. It loads no third-party code and makes no requests to GitHub.

## Build and preview

From the repository root:

```sh
python3 tools/build.py
python3 -m http.server 8000
```

Then open http://localhost:8000. The site uses clean folder URLs, so preview it through the server above; opening the files directly from disk is not supported. See [tools/README.md](tools/README.md) for details.

## Structure

```
README.md          this file
LICENSE            MIT license
.gitignore
robots.txt         allows crawling and points to the sitemap
sitemap.xml        every page, generated by the build
404.html           the not-found page
manifest.webmanifest
_headers           security headers for hosts that read this file
index.html         the landing page
guide/             the guide index, and one page per task group (find-and-open/, organize/, ...)
privacy/ install/ development/ smart-features/ accessibility/
releases/ whats-new/   release notes, one folder per large release
assets/            icon, screenshots, and the generated stylesheet and script
src/               styles.css and script.js, the readable sources
content/           page copy (pages.py) and release notes (whats_new.py)
tools/             build.py and its README
```

The HTML pages, `sitemap.xml`, and the files in `assets/styles.css`, `assets/script.js`, and `assets/search-index.json` are generated by the build. Do not edit them by hand.

### Writing content

Page copy lives in `content/pages.py`. Each page has a title, a description, a lead sentence, a table of contents, and sections.

The guide is split into one page per task group. The groups and the features in each are listed in `GUIDE_GROUPS` in `content/pages.py`. The build stops if a guide section is missing from every group, or is listed twice. Links to a guide section go to its group page, and old `/guide/#section` links open the right page.

Release notes live in `content/whats_new.py`. Each large release has one entry in `RELEASES`, newest first. An entry has an `id` (the version with dashes, such as `1-6-0`), the `version`, the `tag`, the release `date`, a one-sentence `summary`, an `intro`, and sections of plain-language items. Add the entry at the top of the list and rebuild. The release page, its index entry, and its sitemap line are created from it.

Patch releases do not get a page.

The "Last reviewed" date and the version the docs were reviewed for are set at the top of `content/pages.py`.

## Deployment

GitHub Pages serves this repository from the `main` branch, from the root folder, at https://deansasek.github.io/library-site. Every internal link is relative, so the site works under that path.

`_headers` sets security headers for hosts that read that file, such as Netlify and Cloudflare Pages. GitHub Pages does not read it.

After a change, rebuild and commit the generated files together with the source changes, so the published site matches the sources.
