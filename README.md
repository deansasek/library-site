# Library

Everything you open and copy, one shortcut away.

This is the website for Library, a menu bar app for macOS. It is live at [getlibrary.app](https://getlibrary.app).

The app, its source code, and its releases live in the [library repository](https://github.com/deansasek/library).

## What the site contains

- A landing page that introduces Library and links to the install steps.
- A guide to every feature, setting, and permission.
- Pages on privacy, installing and updating, smart features, accessibility, and development.
- Release notes for each major and minor version, with a page for each one.

The site is static. It is plain HTML and CSS, with one small script for copy buttons and docs search. It loads no third-party code and makes no requests to GitHub.

## Build and preview

You need Python 3. From the repository root, build the site and start a local server:

```sh
python3 tools/build.py
python3 -m http.server 8000
```

Then open http://localhost:8000.

The build writes the generated pages, CSS, and script into this folder. Edit the sources, rebuild, and refresh the browser.

To check the latest release against the version the docs were reviewed for, run the build with `--check-release`. It prints a warning if they differ. A network failure only prints a note.

## Repository layout

```
src/          styles.css and script.js, the readable sources
content/      page copy (pages.py) and release notes (whats_new.py)
tools/        build.py, which writes the site
assets/       app icon, screenshots, and the Buy Me a Coffee image
CNAME         the custom domain
```

The HTML pages, `styles.css`, `script.js`, `sitemap.xml`, `robots.txt`, and `search-index.json` are generated by the build. Do not edit them by hand.

## Writing content

Page copy lives in `content/pages.py`. Each page has a title, a description, a lead sentence, a table of contents, and sections.

Release notes live in `content/whats_new.py`. Each large release has one entry in `RELEASES`, newest first. An entry has an `id` (the version with dashes, such as `1-6-0`), the `version`, the `tag`, the release `date`, a one-sentence `summary`, an `intro`, and sections of plain-language items. Add the entry at the top of the list and rebuild. The release page, the index entry, and the sitemap line are created from it.

Patch releases do not get a page. The build does not add one for them.

The "Last reviewed" date and the version the docs were reviewed for are set at the top of `content/pages.py`.

## Deployment

GitHub Pages serves this repository from the `main` branch, from the root folder. The `CNAME` file sets the custom domain to `getlibrary.app`. Point the domain's DNS records at GitHub Pages as described in GitHub's documentation.

`_headers` sets security headers for hosts that read that file, such as Netlify and Cloudflare Pages. GitHub Pages does not read it.

After a change, rebuild and commit the generated files together with the source changes, so the site on `main` matches the sources.
